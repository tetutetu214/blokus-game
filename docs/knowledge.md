# KADO 開発ナレッジ

開発中の判断・知見・ハマりどころの記録。

## 設計判断

### LOCAL 2P モードの実装方式（2026-06-07）

**決定**: 4人エンジン（4色・4コーナー・4ピースセット、ターン `% 4`）を作り替えず、`teamOf()` でチームに束ねる方式で2人対戦を実装。

- **採用したルール**: 本家ブロックス公式の2人ルール（1人2トレイ・対角2色を担当し盤をフル活用）。ただし見た目は1人1色に統一し、自分のピースは色＝1チームとして一体で扱う（自陣同士は辺接触NG・角接触OK）。
- **チーム割り当て**: `teamOf(slot) = slot % 2`。P1=チーム0=slot{0,2}（青・角[0,0]と[m,m]）、P2=チーム1=slot{1,3}（橙・角[0,m]と[m,0]）。対角ペアになる。
- **理由**: コアロジック `game-logic.js` と既存テスト111件を無改造で再利用でき低リスク。`teamMode=false` のとき `teamOf` は恒等写像になり4人モードの挙動が完全不変。変更は `canPlace`/`getCornerPositions` の `=== player` を `teamOf(...) === teamOf(player)` に置換する数行＋UI層に集中。
- **却下案**: 「2色だけ・2コーナーの純粋1対1」。盤の半分が空く＋エンジンを根本から作り替える必要があり高コスト。本家ルール（2トレイ）なら20×20盤でも盤が埋まる。
- **各トレイの初手**: `isFirstMove`/`getStartCorner` はスロット単位のまま据え置き（各トレイが自分の角からスタート）。初手後は同チームの全ピースに角接続できる。

**実装ファイル**: `js/game-logic.js`（teamOf追加・state.teamMode・比較置換）、`index.html`（メニュー/PLAYERS_LOCAL_2P/startGame・resumeGame分岐/endGame・showScores 2チーム表示/セーブラベル）、`js/test-logic.js`（チームモード18件追加）。

**ハマりどころ**:
- Codex委譲時、`index.html` 全体を再インデントされ diff が3500行に膨張 → `git checkout HEAD -- index.html` で戻し、`git diff -w` の実変更9箇所だけを手で再適用して最小diff化（144行）。
- Codexは `resumeGame`（`state.gameMode` を使う関数）にうっかり `mode === 'local2p'` の分岐を入れていた。`resumeGame` に `mode` 変数は無いのでバグ。手動再適用時に `state.gameMode === 'local2p'` に修正。
- ヘッドレスPlaywrightでの盤クリック配置は4P/2P両方で失敗（ヘッダー/ステータスバーが座標を吸う想定のハーネス問題）。本番稼働中の4Pは実ユーザーが遊べているため配置は正常＝機能バグではないと差分テストで確認。

## 学習済み概念

理解度テストで確認済みの概念（次回以降スキップ判定に使用）。

- **本家ブロックス2人ルール / チーム方式の本質**（2026-06-07）: 2人対戦でも4色とも盤に出る（1人が2トレイ＝2色を交代で置く）。エンジンを4人のまま `teamOf` で束ねることで既存テストを無改造で再利用できる。トレードオフは各人が2トレイを管理する操作の複雑さ。※初回テストで「2色だけ使う」と取り違え → 再テストで「全部オレの色として一体扱い」を正答し定着。
